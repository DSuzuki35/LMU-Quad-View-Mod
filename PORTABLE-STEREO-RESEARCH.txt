PORTABLE STEREO RESEARCH 2

STATUS

The portable D3D11 two-eye submission proof is implemented. A single instanced
draw produces two independent eye images with correct parallax and depth. It
uses standard D3D11 capability checks, vertex-stage array routing where supported,
and a geometry-shader routing fallback. No NVIDIA API is required by this path.

This build DOES NOT yet replace LMU's focused-eye renderer or reduce its draw
calls. It adds the bounded game draw audit needed to select and convert the first
LMU shader/pass family. Ordinary LMU rendering remains the current legacy path.
No in-game CPU or FPS improvement is claimed for this research package.

CHANGES AFTER THE FIRST LIVE CAPTURE

The first captures completed but filled the 1,024-object shader cache. Many of
those objects contained identical programs (96 unique programs in 1,024 objects).
This build shares reflection/optional bytecode by stage and SHA256, and keeps up
to 32,768 object aliases and 8,192 unique programs. Reflection and optional raw
program storage are bounded to 16 MiB and 64 MiB respectively. Cache overflow
is reported. Only definitions used by the sampled draws are written to JSON.

Input-layout/shader creation is now observed from main-executable D3D11 device
creation after XR instance initialization, rather than waiting for xrCreateSession.
Runtime/provider helper devices are ignored. Session confirmation preserves the
early metadata when its immediate context matches. This cannot recover definitions
created before interception, or guarantee coverage if device creation comes from
another DLL. The log and metadata_cache.early_device report early interception.

An optional, default-off shader-program capture supplies actual DXBC for local
conversion work. It only exports unique programs used by the sampled focus views;
the rest of the startup shader cache stays in memory. It is disabled when either
the draw audit or master diagnostics is off. These files are never packaged or
included in source contributions. Existing files are reused only if their SHA and
size match, and are never overwritten.

GAME DRAW AUDIT

1. Extract the whole research ZIP into a separate writable folder. Keep the
   working candidate 5 package as rollback. Use the same provider/runtime setup.
2. In Setup, enable diagnostics and logging, and tick:
       Record stereo draw audit (Ctrl+Alt+F8)
   Leave ordinary render profiling unticked for this diagnostic run.
   For the first LMU pass conversion, also tick:
       Include shader programs for stereo conversion
   This saves local game program files as described below.
3. Launch LMU, load a track and wait until the scene/shaders have warmed up.
4. Keep LMU focused on the desktop. Press and release Ctrl+Alt+F8 once while
   driving or viewing a stable replay segment. Two scene frames are recorded.
   This capture reads substantial D3D state and can cause a noticeable hitch.
5. Close LMU normally. Look in this package's logs/ for stereo-audit-*.json,
   quad-*.log and its matching *-run.json. The log should contain:
       portable_stereo capabilities ...
       stereo_audit armed ...
       stereo_audit complete reason=frames frames=2 ...
   Normal close saves a partial capture too, including other-thread teardown.
   If shader capture was enabled, keep logs/stereo-shaders/ alongside the JSON.
6. Untick the draw audit and relaunch before ordinary play or FPS comparisons.
   Audit hooks add overhead while armed. These are compatibility diagnostics,
   not timings suitable for measuring an optimization's performance.

The shortcut can record another segment in the same session after releasing the
key. Pressing it again during a capture saves early. A ten-second timeout ends
a capture that cannot collect two scene frames, provided XR frames continue.
At most 4,096 draws per view per sampled frame are retained; overflow is reported.
The master diagnostics checkbox overrides the saved audit-on preference.

CAPTURE CONTENTS AND LIMITATIONS

The JSON includes draw types/arguments, native render-group IDs, shader IDs and
SHA256 hashes, available shader reflection metadata, input layouts, vertex/index
signatures, VS/PS constant-buffer bindings with observed write generations,
render-target dimensions, and first-16-slot PS texture/sampler signatures.
It records snapshot overhead separately from original draw-API wall intervals.

The JSON contains no raw game shader bytecode, mapped-buffer content, image dump
or system identity. If explicitly enabled, separate local .dxbc files contain
the game's compiled shader programs and can contain embedded compilation metadata.
They are development inputs, not redistributable mod source; keep them out of
GitHub. The repository ignores .dxbc files and stereo-shaders folders. This option
does not upload anything. Shader definitions created before audit hooks may
be unavailable. Mapped WRITE memory is never read. Resource IDs/write generations
are not content hashes, and matching signatures do not prove common object
identity or stereo replay safety. Other shader-stage resources, GPU RT/UAV writes,
worker contexts and Context1 update variants need further dependency analysis.
Command-list execution advances a conservative resource epoch. Indirect draw
arguments are not read back. Partial scopes and truncated records are explicit.

Optional local summary with Python 3:
    python tools/analyze_stereo_audit.py logs/stereo-audit-<capture>.json

The original focus draw calls are all forwarded. The native build/ABI guards,
provider configuration and existing image acquisition/release behavior remain.
Diagnostic JSON and run files stay out of source commits.

Tests cover real device-factory interception, keeping pre-session input layouts,
more than 1,024 distinct programs, shared program definitions, used-only output,
optional local DXBC export/reuse, diagnostics-off, and cross-thread normal close.

HARDWARE PROOF TOOL

Run tools/check-hardware-stereo.cmd to exercise the standalone proof on the
default hardware adapter. It creates its own offscreen D3D11 device, does not
attach to LMU, and saves tools/hardware-stereo-check.log. No headset is needed.
The equivalent console command is:
    tools/PortableStereoCheck.exe --hardware

Tests compare one paired draw with two reference eye draws, including asymmetric
views, parallax, near/far depth occlusion, array-slice copy-out, existing instances,
nonzero IA base-instance offsets and adapted instance-data step rates. Both direct
array routing and the geometry fallback run when supported. The default tool
without --hardware tests Microsoft's WARP software device instead.

WARP and an NVIDIA RTX 4080 passed locally. The design is vendor-neutral; actual
AMD/Intel driver compatibility/performance still needs real-device testing.
Any first LMU pass conversion follows this audit and must preserve per-eye
constants, history, visibility and resource lifetimes before enabling paired draws.
